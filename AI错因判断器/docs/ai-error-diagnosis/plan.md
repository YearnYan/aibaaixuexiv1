# AI 错因判断网站实施计划

## 背景与问题

教师和学生需要从原题、学生原始答案及作答过程出发，定位第一个真正导致后续错误的位置。系统不能用“粗心”“不会做”等模糊标签代替诊断，也不能只根据最终答案猜测原因。

## 范围

- 提供单页面错因判断工作台，支持学科、题目文件、学生答案和补充分析材料。
- 支持 PDF、DOC、DOCX、PNG、JPG、JPEG 文件，单文件不超过 20MB。
- 调用真实的 OpenAI 兼容模型，生成六模块结构化诊断报告。
- 对数学、物理、化学、生物、地理等学科的符号和公式执行统一 LaTeX 规范、服务端校验与网页渲染。
- 支持将完整诊断报告下载为分页稳定的 PDF 和正文可编辑的 Word 文档。
- 提供独立 AI 配置页、配置持久化和模型连通性测试。
- 适配桌面端与移动端。

## 非目标

- 不建设用户、班级、题库或历史报告管理系统。
- 不长期存储题目、学生答案、诊断报告或其他学生数据。
- 不自动替代教师作出最终教学判断。
- 不提供在线编辑 PDF、Word 或历史导出文件管理。

## 设计边界与约束

- API 密钥仅存于服务端，不返回给浏览器，不写入日志。
- 题目文件仅在请求内存中处理，请求结束后释放。
- 信息不足或证据冲突时必须设置“需要教师复核”。
- AI 输出必须经过服务端结构校验后才能呈现。
- 所有学科公式必须使用 `\(...\)` 或 `\[...\]` 分隔；化学式使用 `\ce{...}`，不得向用户暴露未渲染的 LaTeX 命令。
- 网页、PDF 与 Word 必须使用同一份规范化报告；PDF 模块不能在页尾被切成两半；Word 正文和所有公式都必须使用原生可编辑结构。
- Word 公式必须写为 Office Math Markup Language（OMML），禁止使用图片、SVG、文本截图或任何不可编辑降级方案。
- 导出文件仅在请求内存中生成并立即返回，不写入服务器磁盘。
- 页面视觉以 `UI.png` 为唯一基准，保持冷白底色、青绿主操作与红色错误链路。
- 公网部署必须通过 `ADMIN_PASSWORD` 保护配置接口，并使用 HTTPS。

## 高层实施计划

1. 建立 Express 服务、静态页面与配置存储。
2. 实现 PDF/Word/图片材料解析和结构化 AI 分析。
3. 完成主页面、补充材料弹窗、报告六模块和响应式布局。
4. 完成 AI 配置页、密钥保护和连通性测试。
5. 执行单元测试、静态检查和真实浏览器验收。
6. 建立统一公式管线、PDF/Word 导出服务和下载交互。

## 验证

- `npm test` 验证配置、输入校验和无密钥错误路径。
- `npm run check` 验证全部 JavaScript 语法。
- Playwright 验证桌面端、移动端布局以及上传、弹窗、配置页面交互。
- 使用有效模型密钥时，通过配置页连通性测试和真实题目诊断验证完整链路。
- 使用数学、物理、化学、生物、地理代表公式验证网页、PDF 和 Word 三种载体。
- 将 PDF 页面渲染为 PNG，检查模块跨页、页边距、文字切割、公式缺失和重叠。
- 解包 Word 检查正文为 `w:t`、公式为 `m:oMath`，并断言公式区域不存在图片关系或媒体文件。
- 使用 WPS 打开并修改代表公式，再保存、重新解包，确认修改后的 OMML 仍可读取且视觉排版正确。

## 回滚

- 停止 Node.js 服务即可停止全部行为；系统不修改外部数据。
- 删除 `data/ai-config.json` 可恢复到环境变量或默认配置。
- AI 提供商异常时可在配置页切换回上一组地址与模型。
- 导出服务异常时可移除导出路由和按钮，不影响题目分析与网页报告。
