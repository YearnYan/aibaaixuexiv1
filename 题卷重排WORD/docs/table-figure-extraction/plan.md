# 题目表格图形化识别计划

## 问题陈述和动机

试卷中的列联表、统计表、临界值表等具有明确的网格、合并单元格和空间布局。当前识别协议没有明确要求把表格作为题图返回，视觉模型可能将其转写为 Markdown 表格，导致网页出现管道符和分隔行，且用户无法使用现有题图裁切工具修正边界。表格的真实信息不仅是单元格文字，还包含行列关系、表头层级、边框和空白位置，因此应优先保留原卷图像。

## 范围

- 将试卷中的表格定义为题目图形的一种，要求视觉识别返回所属页和归一化边界。
- 支持同一道题包含一个或多个表格，并按页面阅读顺序进入题图列表。
- 当表格图形已成功返回时，从题干中删除重复的 Markdown 表格表示，避免网页和 Word 重复。
- 复用现有题图裁切、实时预览、手动微调和 Word 图片导出链路。
- 兼容模型把表格放在 `figures` 或独立 `tables` 字段中的常见响应。

## 非目标

- 不把表格重建为 HTML 表格或 Word 原生表格。
- 不对没有图像来源的纯 DOCX 表格进行页面坐标推断。
- 不在缺少有效表格边界时删除题干中的表格文字，避免信息丢失。
- 不改变普通题图、选项、公式和题目排序行为。

## 设计边界和约束

- 表格裁切必须包含完整外边框、表头、全部数据行列，不包含相邻题干或其他表格。
- 只有同一道题已获得至少一个 `kind=table` 的有效图形时，才允许移除题干中的 Markdown 表格块。
- 旧模型未返回 `kind` 时保持兼容；可根据独立 `tables` 字段或明确的表格说明推断类型。
- 表格与普通图形共享 `bbox` 坐标、裁切和导出实现，避免建立平行图片系统。

## 高层实施计划

1. 扩展识别图形契约，增加 `kind: diagram | table`，并加强视觉模型提示词。
2. 在共享层实现 Markdown 表格块检测和安全移除。
3. 服务端规范化 `figures`/`tables`，仅在表格图形有效时去除重复表格文本。
4. 客户端保留图形类型并生成对应裁切图片，继续使用现有微调界面。
5. 增加识别协议、字段兼容、文本去重和数据保留回归测试。

## 验证

- 类型检查、后端冒烟测试和生产构建通过。
- 标准多行 Markdown 表格和压缩为单行的表格均能在存在表格图形时被移除。
- 没有有效表格图形时，原表格文本必须保留。
- `figures.kind=table` 和独立 `tables` 两种响应都能生成有效题图数据。
- 浏览器页面中题干不再出现 `|`、`:---:` 等表格源码，表格图片位于题目下方并可进入裁切微调。

## 回滚

该变更没有数据迁移。若识别兼容性异常，可回退图形类型和表格去重逻辑；旧题目数据中的无类型图形仍保持可用。
