# 富内容渲染模型

## 核心数据类型

- `text`：普通正文，React 负责转义显示。
- `math`：已标准化的 LaTeX 内容，包含行内/独立显示标记和是否由容错恢复的状态。
- `svg`：经过白名单净化的完整自包含 SVG，同时携带可访问文字描述。

## 处理链路

1. 输入归一化：统一换行、空格和蕴含箭头，折叠无意义的连续重复箭头。
2. SVG 提取：识别原始标签、代码围栏和 HTML 实体转义。
3. SVG 净化：只保留教学图示所需元素和属性，拒绝脚本、嵌入 HTML、事件、外链和危险 URL。
4. 公式分段：优先处理显式定界符；缺失闭合符时按行或段恢复边界。
5. 裸公式识别：仅在存在 LaTeX 命令、上下标、关系运算、化学式或明确单位等语法证据时进入公式渲染。
6. 公式标准化：把反斜杠中文命令转为 `\\text{}`，统一蕴含命令并补足缺失花括号。
7. 渲染与回退：KaTeX 成功时输出 HTML+MathML；失败时转换为可读 Unicode/普通文本。

## 安全边界

- SVG 不允许 `script`、`foreignObject`、`iframe`、`object`、`embed`、`style`、外部 `image/use` 和动画元素。
- 所有 `on*` 属性、脚本协议、外部 HTTP 地址和非内部片段 URL 均拒绝。
- SVG 必须包含至少一个实际图形或文字元素，否则回退为简洁提示。
- 普通文本始终通过 React 文本节点输出，不使用未经净化的 HTML。

## 一致性

- 网页与 PDF 使用相同的 RichText DOM 渲染结果。
- Word 数学段转换为原生 Office Math；SVG 段写入可编辑的图示说明，不写入源码。
- 板书竖杠清理只作用于普通文本，公式和已净化 SVG 不被破坏。
