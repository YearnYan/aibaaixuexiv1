# K12 教辅资料生成器

一个面向 K12 老师的教辅图片生成工作台。老师可以输入提示词，也可以上传知识库和参考风格图，然后点击“生成教辅图片”批量生成图片格式教辅资料；系统会在后台先确认生成规则，再正式生图。

## 本地运行

1. 可选复制环境变量文件，用于端口、超时和并发等运行参数：

```powershell
Copy-Item .env.example .env
```

2. 启动服务：

```powershell
npm run dev
```

默认访问地址为 `http://localhost:5173`，AI 配置后台为 `http://localhost:5173/admin.html`。生成规则确认接口和 AI 生图接口必须在后台填写，`.env` 不再承载任何 AI 接口配置。

首次注册的账号会自动成为管理员；后续账号默认为普通用户。普通用户进入生成器后需要先登录，管理员登录后才能查看 `/admin.html` 的 AI 配置和积分管理后台。

## 检查与部署

```powershell
npm run check
npm run smoke:worker
npm run deploy:dry
```

`npm run smoke:worker` 使用本地 mock KV 和 mock AI 接口，不会调用生产 AI 网关，也不会消耗真实积分；测试套件带 55 秒硬超时。它会验证线上关键链路：

- 首个注册账号自动成为管理员，普通用户不能访问管理员积分后台。
- 管理员可以生成积分卡密，普通用户可以兑换积分并看到积分流水。
- 普通用户不能读取 AI 配置后台，管理员可以保存 AI 接口配置，配置会联动 `/api/health`。
- 上传参考图时，Worker 不直接调用容易超时的 `/images/edits`；规则确认阶段已完成风格分析，用户确认后直接复用规则调用 `/images/generations`，不再插入第二次视觉模型请求。
- 验证 HTTP(S) partial URL 可立即显示、Base64 按 48 KiB 小事件分块预览、慢持久化时预览仍先到达、partial 后断流不会重复整轮生图。
- 验证图片已到浏览器但持久化失败时保留本地副本并退款，以及取消和单图结果状态写竞态不会恢复已取消批次。
- 严格 4K 尺寸请求遇到 `502/503/504/524` 或结果未知错误时只执行一次模型操作，不自动重生成，也不降级到 `size:auto`。

Cloudflare Worker 配置在 `wrangler.toml`，线上入口为 `src/worker.js`，静态资源目录为 `dist/cloudflare-assets`。上线前应先运行以上三条命令，再执行：

```powershell
npm run deploy
```

## 设计要点

- 前端生成器不保存、不暴露模型密钥；管理员在后台填写的配置保存到本地 `data/ai-config.json`。
- 用户、登录会话、积分余额、兑换卡密、积分流水和生成扣退记录保存到本地 `data/app-state.json`，该文件包含账号与运营数据，不提交到版本控制。
- 每生成 1 张图片消耗 1 积分；规则确认阶段不扣积分，正式生图前会按最终张数提醒用户确认，确认后由服务端预扣积分。
- 提示词仅校验是否为空，不限制最少字数；AI 推荐数量超过当前积分时，可选择购买积分，或按现有积分对应的图片数量重新规划并继续生成。
- 单张图片生成失败、请求中断或批次异常时，服务端会按未成功图片数量退回积分，并在积分管理后台展示预扣、成功、失败和退款记录。
- 用户右上角可兑换积分，购买积分按钮会跳转到 `https://gongtouai.top`。
- 服务端代理调用 OpenAI 兼容网关，支持纯提示词生成与参考图生成。
- 生成规则确认和 AI 生图各有独立接口池；每个接口池可配置多个 `URL / MODEL / APIKEY`，同一 URL 下可填写多个 KEY。
- 后台配置是唯一 AI 配置来源；后台为空时对应 AI 功能不可用。
- 不同图片会在接口池内轮询 URL/KEY；单张图片结果未知时不自动串行重试，只有上游明确拒绝流式参数时才安全回退同步协议。
- AI 生图后台支持 `4K` 和 `其他` 分辨率档位；选择 `4K` 时会按当前图片比例生成接近 4K 的 `size` 参数，并满足 `gpt-image-2` 的最长边、像素量、16px 对齐和 3:1 比例约束。
- Cloudflare Worker 线上模式下，参考风格图默认先转成风格描述再参与 4K 文生图，避免参考图编辑接口长时间等待导致 `524`。
- 生成规则包含完整知识库蓝图时，确认扣分后的正式请求不再重复上传原始 PDF 和页面截图，图片模型可更快收到生图请求。
- 本地 Node 与 Cloudflare Worker 都优先使用上游 SSE；HTTP(S) 图片 URL 直接预览，Base64 图片按 48 KiB 分块送到浏览器组装为 Blob，因此页面不再等待 KV 保存或传播，同时不存在巨型单行控制事件。
- 批量模型请求保持既有 2/3 路并发窗口；完整预览先于持久化槽等待，图片保存完成即释放持久化槽，积分记录不占模型或持久化槽，既不阻塞下一张模型请求，也不会无限堆积 4K 产物。
- 前端按单张结果增量更新，不会在其他图片返回时销毁并重新加载已经显示的图片。
- 图片已完整到达浏览器但云端持久化失败时，前端保留“仅本地”副本供预览、下载和作为参考图，并明确显示未保存及本张已退款。
- Cloudflare Worker 在同一实例内有序执行生成预扣、结果记录、取消和结算；Workers KV 仍是最终一致存储，跨节点强一致场景需要迁移到 Durable Objects 或其他强一致存储。
- 批量数量可由用户填写；不填写时，后台规则确认会由 AI 判断合适数量，当前保护上限为 120 张。
- 生成图片前会自动确认生成规则，服务端会结合提示词、知识库和参考风格图梳理任务意图、全量内容盘点、主题层级、覆盖映射、内容生产策略和逐张规划；PDF 页码、截图页码和图片数量仅作为内容识别证据。
- 生成数量决策以 AI 对整体内容的规划为最高权重：先理解用户目标和知识库主题层级，再按章节、知识点、题型、练习组、图表和教学任务等内容单元决定数量；原文件页数、PDF 页数、截图数量、上传图片数量和文件数量都不作为数量依据。
- 对高密度知识库，规则确认会按知识簇、单张可读性和记忆负荷拆分图片；清单型资料优先做速查卡，流程型资料优先做步骤卡，题目型资料按题型组或能力点拆分，避免把原文件密集页面硬塞成一张图。
- 逐张图片的内容顺序按教学逻辑和内容板块重排，原文件页码只作为来源证据，不决定第几张图放什么内容。
- 图片比例支持“与参考图比例一致”，前端会按当次参考风格图真实宽高换算比例。
- 失败图片卡片出现后可立即重试本张，多张失败图片可以同时重试。
- 不上传参考图时，图片类型、内容结构和视觉风格由用户提示词与知识库决定；系统不再默认套用练习单、工作表、作答区、答案区或固定可打印模板。
- 仅当 AI 没有返回有效数量或页面规划时，服务端才会按标题、知识点、题型、主题层级和文本密度做兜底；AI 的有效内容规划优先，不再用程序估算覆盖 AI 的推荐数量。
- 参考风格图会作为唯一视觉设计模板处理；有参考风格图时，知识库图片只提供内容依据，不再作为视觉参考污染版式。
- 上传参考图会先在浏览器端压缩，降低请求体积和生成失败率。
