# K12 教辅资料生成器设计计划

## 问题陈述和动机

K12 老师在备课、课堂活动、作业布置和复习讲评中，需要快速产出练习单、知识卡、课堂活动页、海报式讲解图等教辅资料。传统制作方式依赖排版软件和素材搜索，耗时较长，且批量变体生成成本高。

本功能提供一个网页工作台，让老师通过中文提示词、知识库文件和可选参考图片生成图片格式教辅资料。用户只需点击“生成教辅图片”，前端会在后台先执行生成规则确认，由 AI 自动梳理内容覆盖逻辑和最终数量，再继续正式生图。规则确认已经得到完整知识库蓝图时，正式生成不得重复上传和解析原始知识库；模型返回可识别图片后必须立即预览，同时继续保存本地结果，不能让用户等待持久化或整批完成。

## 范围

- 搭建可本地运行的网页应用。
- 提供教辅生成表单、参考图上传、批量数量控制、结果预览和下载。
- 提供服务端代理接口调用图片生成网关。
- 提供 AI 配置后台，允许管理员配置生成规则确认和 AI 生图的 OpenAI 兼容接口池。
- 提供用户注册、登录、退出、当前用户信息和积分兑换能力；首个注册账号自动成为管理员。
- 提供积分管理后台，管理员可查看用户积分、生成扣费、失败退款、积分流水和兑换卡密，并可直接调整用户积分。
- 提供生成规则确认接口，前端在正式生图前自动调用，用于梳理推荐数量、批量图片的内容拆分、合并、排序和覆盖逻辑。
- 提供端到端流式生成接口，上游一返回可识别图片就逐张展示，保存完成后再无缝切换到本地结果地址。
- 支持纯文本生成和参考图生成两种路径。
- 将 AI 接口配置只保存在后台配置文件中，生成器前端不接收密钥。

## 非目标

- 不实现班级管理、在线支付闭环和历史云端存储。
- 不实现复杂模板编辑器或图片二次编辑画布。
- 不在前端硬编码或展示真实密钥。
- 不自动调用生产图片生成接口做验收，除非获得明确确认。

## 设计边界和约束

- 图片生成模型、网关地址和密钥只允许通过后台配置，后台可配置多个 OpenAI 兼容接口。
- AI 配置后台和积分管理后台只允许管理员账号访问；用户端不展示 AI 配置后台入口。
- 用户必须登录后才能使用生成规则确认和正式生图能力。
- 规则确认阶段只确定最终图片数量和逐张规划，不扣除积分。
- 正式生图前，前端必须按最终图片数量提示本次会扣除的积分；用户确认后，服务端按 1 张图 1 积分预扣。
- 批次结束、请求中断或服务端异常时，服务端必须按未成功生成的图片数量退回积分，并记录退款流水。
- 用户和积分状态保存到 `data/app-state.json`，该文件包含账号、会话、卡密和积分流水，必须被版本控制忽略。
- 生成规则确认使用独立文本/多模态模型配置，只允许通过后台配置；该配置只影响 `/api/generation-rule`，不影响正式生图。
- 后台配置保存到 `data/ai-config.json`，该文件包含密钥，必须被版本控制忽略。
- 每个接口池可配置多个 URL，每个 URL 可配置多个 KEY；不同图片按 URL 和 KEY 轮询分发，但 URL/KEY 数量不得扩大单张图片的串行尝试次数。
- AI 生图配置支持 `4K` 和 `其他` 分辨率档位；`4K` 档会按当前图片比例计算 `size`，并满足最长边不超过 3840、宽高 16px 对齐、比例不超过 3:1、总像素在模型允许范围内。
- 单次批量生成数量由用户填写，当前本地保护上限为 120 张，前后端都必须校验。
- 正式生成前必须先在后台确认生成规则；规则确认按钮和规则结果默认不显示给用户。
- 批量数量是可选项；用户未填写数量时，规则确认必须返回推荐数量和同等数量的页面规划。
- 规则确认的数量和逐张内容分配必须以 AI 对整体内容的规划为最高权重：先理解用户当次任务意图、目标和知识库主题层级，再做全量内容盘点，分析章节、知识点、题型、练习组、图表和教学任务，最后根据知识簇、单张可读性和记忆负荷决定生成多少张以及每张放什么。
- 生成图片顺序必须按教学逻辑、概念依赖和内容板块重排；原文件页码只作为来源证据，不能决定第几张图呈现哪个内容。
- 图片比例支持“与参考图比例一致”，前端使用当次第一张可读参考风格图的真实宽高换算成自定义比例传给服务端。
- 生成规则确认必须先读取知识库内容证据：可提取文本、标题线索、知识库图片证据，以及扫描型或图片型 PDF 的页面截图样本，用于识别真实主题层级、知识点、题型、图表、案例和教学任务。
- 生成规则确认必须先抽取“知识库蓝图”：把知识库中真实出现或可从截图可靠读取的内容转写为 `anchors[]`，再基于这些锚点做数量决策、逐张规划和覆盖审计。
- 正式生图前，服务端必须重新校验并绑定知识库蓝图锚点；即使前端回传的规则缺少蓝图或单张锚点，也要用本次知识库证据重新接地，确保最终生图 prompt 不退化成泛泛“根据知识库生成”。
- 正式生图 prompt 必须采用单张硬接地策略：规则确认阶段可以全量阅读知识库，但每一次发给图像模型的 prompt 只允许包含当前张规则、当前锚点、当前必含项、当前禁混项和少量全局意图/风格摘要，不得把整份知识库全文或其他页面锚点作为当前张取材池。
- 推荐数量必须由 AI 对用户意图、知识库整体内容和主题层级的规划决定；原文件页数、PDF 页数、截图数量、上传图片数量和文件数量不得作为数量依据，也不得作为推荐数量硬下限。服务端仅在 AI 没有返回有效数量或页面规划时按内容线索兜底。
- 高密度清单、速记资料、知识库型 PDF 不得按原页压缩成密集长图；规则确认必须按知识簇拆成可读、可背、可查的内容成品，并输出内容盘点、数量策略、内容生产策略、风格建议和覆盖审计。
- 若 PDF 文本抽取出现乱码、断字或明显缺漏，规则确认应优先依赖页面截图、知识库图片和标题线索识别内容。
- 参考风格图必须被视为设计模板，正式生图提示词应要求尽量复刻其版式、栏目、配色和视觉元素。
- 当存在参考风格图时，知识库文件只能影响内容，不得作为视觉样式参考传入正式生图，避免污染当次参考图版式。
- Cloudflare Worker 线上运行时不得默认把参考图直接送入 `/images/edits` 长耗时编辑接口；参考图风格说明必须在生成规则确认阶段完成，用户确认扣分后直接复用已确认的 `layoutLogic`、`styleLogic` 和 `styleAdvice` 调用 `/images/generations`，不得再串行调用一次规则/视觉模型。
- 当生成规则包含完整 `knowledgeBlueprint` 和逐页 `knowledgeAnchor` 时，前端正式生成请求不得重复携带原始知识库文件和 PDF 页面截图；字段缺失时才允许回传原始资料供服务端重接地。
- Cloudflare Worker 调用 `/images/generations` 时必须优先使用上游 SSE 流式生图协议，通过 `partial_images` 中间事件维持 Worker 到上游的长连接；只有上游明确返回“不支持 stream/partial_images 参数”时，才允许兼容性回退到同步响应。
- 本地 Node 服务与 Cloudflare Worker 的 `/images/generations` 传输语义必须一致，禁止本地服务继续同步等待约 130 秒代理超时并重复整轮生图。
- 上游返回 HTTP(S) 图片 URL 时允许在持久化前通过 `preview` 事件送达前端；Base64 图片必须按最多 48 KiB 的 `preview_start/preview_chunk/preview_end` 小事件下发，由浏览器组装为临时 Blob 立即展示，禁止巨型 data URL 或单行 Base64 事件。流正常结束或异常中断时只要已有可识别 partial，就直接使用最后一张可用图片，不得重复整轮模型请求。
- 上游流式生图只改变传输方式，不得改变后台配置的模型、URL、密钥、分辨率档位、严格 4K `size` 或批量并发数。
- 模型获取继续使用既有普通 2 路、固定排版 3 路窗口；持久化使用独立且不超过对应模型窗口的有界队列，模型工作线程最多额外持有一份等待持久化的产物，禁止为 120 张批次无限积压 4K Base64 和 Buffer。
- 模型产物形成后，完整预览必须在等待持久化槽之前送达浏览器；图片保存和积分状态写不得占用模型槽，积分状态写也不得延长持久化槽持有时间。
- 前端结果区必须按图片索引增量更新，禁止每收到一个流事件就销毁并重建全部 `<img>`；已显示预览必须保持可见，直到本地保存地址预加载成功后再无缝切换。
- 图片已完整送达浏览器但持久化失败时，最终事件必须明确标记持久化失败；前端保留本地 Blob/HTTP(S) 预览，允许预览、下载和作为参考图，并明确提示未云端保存及积分已退回，不得退化为失败卡片或销毁本地副本。
- Worker 必须记录单张最终失败的阶段、HTTP 状态、尝试次数和总耗时；前端不得再把所有网络错误统一覆盖成同一句“超时”。
- Worker 读取状态时必须自动回收最近活动超过 60 分钟仍为 `running` 的孤儿生成批次，并退回其中所有未成功图片的积分；生成队列、取消标记和积分结算必须使用同一个批次 ID。
- 同一 Worker 实例内的生成预扣、单图结果记录、取消和最终结算必须通过短状态事务有序执行；取消标记先独立写入以尽快阻断后续模型和迟到结果。该机制不把 Workers KV 变成跨边缘节点强一致存储，多实例强一致需求仍应迁移到 Durable Objects 或等价一致性存储。
- 取消信号必须在同一 Worker 实例内先同步发布，再异步写入 KV；所有已启动预览任务必须在等待完成槽前登记并最终收拢，`done` 必须在实际写入流时再次检查取消状态，被抑制时改发明确的取消 `error` 终态。
- 浏览器只有在预览 `<img>` 真正触发 `load` 后才能把持久化失败结果标记为“仅本地”；损坏图片必须转为失败卡片。清空或新批次必须使旧重试回调失效，并释放活动及暂存的全部 Blob URL。
- Cloudflare 入口 HTML 必须为主前端脚本携带发布版本参数，避免部署成功后浏览器继续复用旧 `/app.js` 缓存。
- `4K` 档正式生图必须按比例计算严格 `size`；所有分辨率遇到 `502/503/504/524`、超时、断流、截断响应等“是否已生成未知”的结果都不得自动重复模型调用，也不得改用 `size:auto`。
- 参考图仅用于当次请求，不做持久化保存。
- 生成结果必须保存到 `public/generated/` 或 Worker 生成资源存储，并最终返回 `/generated/...` 本地地址；即时 `preview` 仅用于消除等待，不改变最终结果地址和积分结算依据。
- 网关调用可能存在耗时、失败、部分成功和速率限制，界面需要清晰呈现状态。
- 图片模型操作默认只执行 1 次；仅当上游以 `400/422` 明确拒绝 `stream`/`partial_images`、能够确认模型尚未受理时，才允许移除流式字段做一次协议回退。失败图片立即退款，并由用户通过单张重试显式发起新操作。
- 失败结果卡片应在出现失败后立即允许单张重试；多张失败图可以同时重试，且不阻塞仍在进行的整批生成。
- 固定排版模式先生成第 1 张母版，再并发生成后续页面以提升速度。
- 资料类型和使用场景默认均为不限。
- 图片类型、内容结构和视觉风格应由用户提示词、知识库内容和参考图共同决定；不默认套用练习单、工作表、作答页、答案页或固定可打印模板。

## 高层实施计划

1. 建立 Node 原生静态服务和 API 代理。
2. 建立前端工作台：任务表单、参考图上传、批量数量、结果画廊。
3. 在服务端实现请求校验、提示词组装、参考图转换和并发控制。
4. 补齐环境变量示例和中文说明文档。
5. 将生成结果改为先落盘、再流式返回前端。
6. 新增生成规则确认流程，并将确认规则注入后续图片生成提示词。
7. 新增 AI 配置后台和轮询调度。
8. 新增用户登录、积分扣退和积分管理后台。
9. 运行静态检查并启动本地服务验证页面。

## 验证

- 使用 `npm run check` 验证本地服务端、Cloudflare Worker 和前端脚本语法。
- 使用 `npm run smoke:worker` 验证 Worker 认证/积分主流程、知识库蓝图接地、参考图稳定路径、未知结果单次模型操作、partial 断流兜底、无事件名 SSE、Base64 分块预览、慢 KV 下的有界持久化、显式协议回退、严格 4K 尺寸、既有批量并发和孤儿批次退款；套件必须在 55 秒看门狗内结束。
- 使用 `npm run deploy:dry` 先同步 `public/` 静态资源到 `dist/cloudflare-assets/`，再验证 Cloudflare Worker 打包和 KV/Assets 绑定。
- 启动 `npm run dev` 后访问本地页面，确认静态资源和健康检查可用。
- 访问 `/admin.html`，确认后台配置表单在桌面和移动视口下可用。
- 调用 `/api/admin/ai-config`，确认可读取和保存后台配置，且坏 URL 会被拒绝。
- 在未配置密钥时提交生成请求，应返回明确的配置错误。
- 配置密钥后，点击“生成教辅图片”应先自动完成规则确认，再使用最终数量和同等数量的页面规划生成图片。
- 对多页 PDF 知识库，规则确认应读取文本量、标题线索和 PDF 页面截图证据来识别主题层级；数量决策必须以任务意图、内容覆盖和内容单元规划为主，而不是按页数、截图数或文件数对应。
- 对页数较少但包含大量独立场景/模板/编号条目的 PDF，`npm run smoke:worker` 必须验证模型即使误返页数级数量，服务端也会按知识库锚点和编号标题线索抬升到完整内容单元数量。
- 正式生图 prompt 必须包含当前页知识库蓝图锚点、真实内容和必含词；当规则或前端缓存丢失锚点时，服务端必须在进入生图接口前恢复锚点，并确认 prompt 不包含其他页面的专属知识点或必含词。
- 配置密钥后，生成请求应返回与填写数量一致的结果，并允许部分失败展示。
- 配置密钥后，前端应逐张展示 `/generated/...` 本地保存图片地址。
- 生成规则已包含完整知识库蓝图时，确认扣分后的正式请求体不得再次包含原始 PDF 和页面截图；图片模型请求应在积分预扣和轻量规则校验后立即发出。
- 收到 `preview` 后只更新对应结果卡片；后续其他图片事件不得让已经显示的图片重新加载或短暂消失。
- 任意下行 NDJSON 单行必须小于 64 KiB；禁止 `data:image/` 和 `b64_json`，只有 `preview_chunk.data` 可携带最多 48 KiB 的 Base64 分块；结果事件需携带模型阶段和持久化阶段耗时。
- 在图片持久化和应用状态写分别被阻塞的回归中，所有已完成模型产物的 `preview_end` 必须先到达，后续模型仍按既有窗口派发；释放阻塞后结果事件才能完成。
- 持久化失败回归必须验证浏览器保留本地副本并可下载；取消与单图成功状态写竞态回归必须验证最终状态仍为 `canceled`、积分只退款一次且取消后无迟到成功事件。
- 浏览器 DOM mock 必须覆盖 URL-safe/无填充 Base64、非末块四字符对齐、坏 Blob 降级、清空与重试竞态、无新预览的成功重试 Blob 回收，以及固定排版不得提交浏览器私有 `blob:` 母版。
- Cloudflare dry-run 构建产物中的 `index.html` 必须引用带发布版本参数的 `app.js`，且构建后的脚本必须包含 `preview_start/preview_chunk/preview_end` 协议处理。
- 选择“与参考图比例一致”且未上传参考图时，前端应阻止提交并提示先上传参考风格图。
- 部分图片失败后，应能在整批未结束时立即点击失败卡片重试；多个失败卡片可并发重试。

## 回滚

- 删除新增项目文件即可回到空项目状态。
- 若某个图片网关参数不兼容，可通过服务端配置或请求构造回退到最小参数集合。
- 若参考图编辑接口不可用，保持 Worker 默认稳定模式：参考图先转风格说明，再走 `/images/generations`；如需恢复直接编辑接口，应先通过 smoke test 和小批量线上测试。
- 若上游明确不支持 `/images/generations` 的 `stream` 或 `partial_images` 参数，Worker 自动对当次请求回退同步协议；回滚不涉及修改模型或后台配置。
- 若上游 partial 事件格式与兼容网关不一致，可回滚为“只使用 completed 作为最终结果”，但必须保留同步最终图片落盘前预览和前端增量渲染，且不得恢复确认后的二次风格模型调用。
- 若严格 4K 尺寸持续触发上游网关超时，不再用 `size:auto` 偷降级，也不在站内串行重做同一张图；应要求网关提供稳定 SSE、幂等键或可查询任务 ID 后再恢复自动重试。
- 若后台配置写错或需要恢复旧配置，重新在后台保存正确接口池即可。
