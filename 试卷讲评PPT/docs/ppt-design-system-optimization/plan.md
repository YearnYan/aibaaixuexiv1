# 试卷讲评 PPT 综合设计优化计划

## 问题陈述和动机

当前应用能够完成上传、识别、预览和导出，但应用外壳与 PPT 画布都依赖大量同质圆角卡片，教师工作场景辨识度不足。PPT 的内容集中在上半屏，短题浪费空间，长题依靠持续缩小字号与截断兜底；图形裁切对小定位框扩张过度，容易把无关试卷区域带入课件。

## 范围

- 重构首页上传区、生成设置、处理状态、预览工作台和操作区的视觉层级与响应式布局。
- 重构 PPT 内页的题干、选项/答案、图形、解题思路和知识点模块。
- 根据题型、图形和内容密度选择选择题、图形题、综合题三类版式。
- 优化题目图形裁切安全边距、输出尺寸与预览适配。
- 增强键盘操作、焦点样式、减少动画偏好和窄屏可用性。
- 保持根目录与 `public/` 三个前端文件内容一致。

## 非目标

- 不修改 AI 请求端点、提示词、响应字段或使用次数校验。
- 不修改 PDF、Word、图片解析与分批传输策略。
- 不把导出的 PPTX 改为原生可编辑文本；继续使用 1600×900 图片铺底。
- 不新增登录、持久化、模板市场或在线协作能力。

## 设计边界和约束

- 现有 slide 数据字段必须向后兼容。
- 任何答案隐藏状态都不能通过样式或辅助文本泄露正确答案。
- PPT 画布保持 16:9；截图导出不得拉伸或裁切。
- 图形以完整可辨识为先，禁止使用 `object-fit: cover` 裁掉坐标轴、标注或辅助线。
- 不引入新的运行时依赖，不使用虚构统计数据或装饰性内容。

## 高层实施计划

1. 采集首页与三类 PPT 基线截图，记录控制台和窄屏问题。
2. 建立“纸白、墨青、朱砂批注色”的应用与幻灯片双层 token。
3. 原子化重构 HTML 语义结构和应用外壳。
4. 增加 slide 视图模型、内容分段与版式分类，重写 PPT DOM 模块。
5. 收紧图形裁切扩张规则，并按图形长宽比调整展示。
6. 用桌面、窄屏、短题、图形题、长题和极端文本执行对抗式审查。

## 验证

- 在 1440×900、1280×800、390×844 三个视口检查首页与预览工作台。
- 对选择题、图形题、综合题和极端长文本逐页截图。
- 检查 `scrollHeight <= clientHeight`、最小有效字号、图片完整性和焦点可见性。
- 检查控制台错误，并验证目录切换、答案开关、重新上传、全屏入口。
- 验证截图归一化结果为 1600×900，根目录与 `public/` 文件哈希一致。
