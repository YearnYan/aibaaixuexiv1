# AI 运行时配置计划

## 背景与问题

当前浏览器端调用 `/api/site/exam-ppt`，本地 Node.js 服务只提供 `/api/chat`；同时，本地缺少共享权限模块时，前端会在请求 AI 前终止。AI 网关、模型与密钥只能依赖环境变量，教师无法在当前运行实例中安全地完成配置和诊断。

## 目标与范围

- 新增 `/ai-config/` 本地 AI 配置页面。
- 在当前 Node.js 进程内管理网关地址、模型、密钥、超时、输出上限和 Temperature。
- 让 `/api/chat` 与 `/api/site/exam-ppt` 共用同一处理链路。
- 让首页在本地服务中跳过共享积分凭证，直接使用本地 AI 代理。
- 提供读取、保存、恢复环境变量和用户主动触发的连接测试。

## 非目标

- 不把 API Key 写入 `.env`、浏览器存储、日志或响应正文。
- 不提供多用户、云端持久化或密钥托管。
- 不替换现有试卷识别、课件编排和导出逻辑。
- 不自动调用外部 AI；连接测试只在用户点击后执行。

## 设计边界与约束

- 配置接口只接受回环地址请求。
- API Key 永不回显；空密钥表示保留当前值，清除操作必须显式声明。
- 所有更新先完整校验，再一次性替换运行时配置，禁止部分生效。
- 服务重启后恢复环境变量，页面必须明确提示这一生命周期。
- UI 延续纸白、墨青、朱砂的教师工作台设计语言，并适配 320px 以上视口。

## 高层实施计划

1. 建立运行时配置模型与本机访问守卫。
2. 新增配置读取、更新、重置和连接测试 API。
3. 合并两个聊天路径的处理器，并让请求使用最新运行时配置。
4. 构建“AI 接线台”配置页与首页入口。
5. 增加前端本地后端探测，接通本地试卷生成链路。
6. 进行接口、安全、桌面、移动端与控制台验收。

## 验证

- 配置读取响应不包含密钥值，并设置 `Cache-Control: no-store`。
- 非法 URL、模型、超时、Token 上限和 Temperature 均被拒绝且不改变旧配置。
- 未配置密钥时，聊天和测试接口返回可操作的错误信息。
- `/api/chat` 与 `/api/site/exam-ppt` 均能进入同一请求校验逻辑。
- 配置页在桌面与 390px 视口无横向溢出，键盘焦点可见，控制台无错误。
