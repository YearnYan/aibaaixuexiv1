# 艾爸AI学习品牌站重构计划

## 问题陈述与动机

当前根目录由多个独立 K12 工具组成，缺少统一品牌主页；各工具前端色系和界面语言不一致，积分管理与 AI 配置又集中在同一后台页面。此次改造需要建立“艾爸AI学习”品牌入口，让用户从同一主页完成登录、注册、积分兑换和工具跳转，同时保持全部既有工具的业务能力与交互流程不变。

## 范围

- 新建占满桌面首屏的品牌主页及响应式移动端版本。
- 使用 AI 生成的无人物位图作为首屏背景，不使用 HTML、SVG 或渐变替代主视觉。
- 展示全部 21 个子站入口，并保留子站原有链接与业务能力。
- 复用现有认证、积分与 AI 配置 API 契约。
- 将积分管理后台与 AI 配置后台拆为两个独立页面。
- 在 AI 配置后台提供全局 AI 接口池，并允许逐个子站选择跟随全局、独立接口或停用。
- 向所有子站同步品牌色系、字体、焦点态和按钮文字对比度规则。
- 为全部子站提供与主页一致的顶部导航；Next.js 子站也必须包含同一导航。
- 建立构建、静态检查和真实浏览器回归流程。

## 非目标

- 不重写子站的 AI 推理、文件处理、导出、扣费或退款逻辑。
- 不变更用户、积分、卡密和会话数据结构；AI 配置仅做向后兼容的 `global/sites` 扩展。
- 不在积分管理后台提供任何 AI 配置入口。
- 不把所有子站合并成单一前端框架。

## 设计边界与约束

- 品牌主色来自 Logo：暖阳黄、象牙白、列车砖红与墨棕；使用少量青绿平衡暖色。
- 主视觉主题为“学习列车驶入知识站台”，不得出现人物、面孔、角色、文字或水印。
- 首屏文案区域必须具有稳定的可读遮罩，桌面和移动端均不与导航或下一段内容重叠。
- 实心深色按钮使用亮色文字；浅色按钮使用深色文字，至少满足 WCAG AA 常规文字对比度。
- 子站仅通过独立主题样式和导航接入覆盖视觉令牌、通用控件状态，不改变原有业务字段和 API 调用。
- 所有配置文档、源码和提交记录不得包含接口密钥。

## 视觉方案

- 色彩：晨光纸白 `#FFF9E8`、暖阳金 `#F6C344`、列车砖红 `#9D321E`、墨棕 `#2B211D`、学习青绿 `#247C78`、纯白 `#FFFFFF`。
- 字体：品牌展示使用 `Microsoft YaHei` 的高字重组合；正文使用 `PingFang SC`、`Noto Sans CJK SC` 与系统无衬线回退；数据与标签使用等宽数字特性。
- 布局：首屏为全幅背景图和左下品牌文案；下一屏使用不嵌套卡片的分组工具矩阵。
- 记忆点：由 Logo 中列车意象延展出的“知识轨道”分组线贯穿工具入口，而不是通用装饰图形。

## 高层实施计划

1. 生成并验收品牌首屏背景图，落入项目资源目录。
2. 实现根主页、认证弹窗、积分兑换弹窗及工具入口矩阵。
3. 按既有 API 契约实现两个独立后台页面。
4. 生成统一子站主题与顶部导航，并接入 HTML、React 和 Next.js 入口。
5. 接通全局/子站 AI 配置到子站进程环境变量，兼容旧版 `rule` 配置。
6. 运行静态检查、单元测试、构建和真实浏览器桌面/移动端回归。
7. 发布前由用户确认 Git 提交、远程仓库和推送范围。

## 验证

- 根站桌面首屏在 `1440x900` 下占满视口且能看到下一段提示。
- 在 `390x844` 下导航、标题、按钮与工具入口无重叠和横向滚动。
- 注册、登录、退出、卡密兑换及两个后台 API 调用保持原路径和载荷。
- 积分后台 DOM、链接和脚本中不存在 AI 配置入口。
- AI 配置后台能看到全局 AI 接口池和 21 个子站的 AI 来源选择。
- 已配置全局 AI 的子站能完成真实生成请求；停用或缺失配置时返回可读错误。
- 抽查全部子站入口能加载主题；深浅按钮文字对比清晰。
- 各项目已有测试单次最长 60 秒，超时即终止并记录。

## 回滚

- 根站为新增目录，可移除根入口与品牌资源恢复到原工具集合。
- 子站品牌主题通过独立 `aiba-brand.css` 接入，移除该链接即可恢复原视觉。
- 后台拆分保留既有 API 契约，必要时可恢复原合并页面，不涉及数据迁移。
