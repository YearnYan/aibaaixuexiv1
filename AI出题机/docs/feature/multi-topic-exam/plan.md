# 多知识点组卷、图形与公式质量改造

## 问题陈述和动机

原出卷流程只接收一个知识点和一个考点，无法表达真实试卷中“多个知识点、多个考点、不同题量与难度”的组卷需求。长卷生成还依赖供应商会忽略的 JSON 模式，并要求模型学习私有公式传输标记，导致非 JSON、嵌套标记、裸公式和无工具调用等高频失败。题图与 PDF 导出链路也必须保证真实图形和 KaTeX 公式不会被占位或错误转换。

题图失败还存在跨层契约不一致：服务端只按字符串正则判断 SVG，浏览器按 XML 解析。含 HTML 命名实体、标签错配、未声明命名空间或不完整路径的响应可能被服务端写入缓存，却被浏览器拒绝；后续重试继续命中同一个坏缓存，形成持续失败。修复必须让 Node、Worker 与浏览器共用同一严格质量门，并让浏览器复检失败能绕过缓存重新生成。

继续生成凭证曾只保存在 Node 进程内存的安全会话对象中。服务重启后浏览器试卷仍存在，但服务端凭证状态消失，导致合格试卷无法继续追加。续题授权必须改为服务端签名、带有效期、可跨进程重启验证的能力令牌，并在每次成功追加后续签。

PDF 截图画布还混合了真实正文与 A4 最小高度、底部内边距等结构性白区。分页若覆盖整个物理画布，会在正文恰好结束于分页线前时生成纯白尾页并被质量门拒绝。修复必须测量最后可见语义内容底边，不能删除空白页检查、降低分辨率或过滤未知页面。

## 范围

- 新增多知识点组卷配置：每个知识点可包含多个考点，每个考点独立设置题量、难度和题型数量。
- 后端按考点与题型分配生成任务，并合并为一份可追溯的试卷。
- 图形生成改为真实批量接口，图形失败时阻止组卷，不提供占位图或静态兜底图。
- AI 生成与审核强制调用唯一 `submit_exam` 工具，只提交题目内容；题号、题型和标题由服务端确定性构建。
- 用户可见内容直接使用标准 `\\(...\\)` / `\\[...\\]` LaTeX，服务端以 KaTeX + mhchem 编译，覆盖题干、选项、答案解析、预览和导出。
- 增加输入校验、公式质量检查、图形质量检查及可回归的接口验证。
- 统一题卡、试卷预览与 Word 中的题图视觉尺寸；底部组卷栏提供可逆的全选/取消全选操作。
- Word 输出标准 `.docx`：KaTeX 的规范 MathML 转换为 Word/WPS 原生 OMML 可编辑公式，题图仍以高清 PNG 嵌入，并执行源码残留阻断。
- PDF 使用对称 A4 内容区和基于实际 DOM 几何范围的原子分页，题目、题图、展示公式和答案解析不得跨页切割。
- PDF 分页终点使用最后可见正文底边，而不是整个 `html2canvas` 物理高度；结构性底部留白不得产生页面，稀疏内容通过原始像素复核。
- 每个知识点、考点、题型结果组提供“继续生成3题”，仍经过相同的严格生成、独立审核、公式与题图质量门。
- 续题凭证不依赖 Node/Worker 进程内存；服务重启后原试卷仍可继续追加，每次成功追加返回新的有效凭证。
- 内容质量错误不得只做无上下文的整任务重生成；裸 LaTeX、定界符、KaTeX、学科表达式和题图描述错误必须携带字段路径与错误码进入失败批次的独立审题纠正，结构错误仍直接拒绝。

## 非目标

- 不重写现有教材知识点 JSON 数据库。
- 不更换 AI 服务供应商或 AI 配置页面。
- 不把题目内容持久化到数据库；本次仍使用当前会话内存与浏览器状态。

## 设计边界和约束

- 保留旧版单知识点请求字段，服务端将其规范化为只有一个配置项，保证已有调用可继续工作。
- 一次组卷最多 30 道题、20 个考点配置；每个考点题量 1–30，温度和密钥等仍由 AI 配置页管理。
- 任何题干含“如图/图中/下图/作图”或 figure 字段的题目，图形必须成功生成并通过 SVG 安全及可渲染校验，否则整次组卷失败。
- 公式数据在接口中保留 LaTeX，不再做 Unicode 降级；页面、PDF 和 Word 使用同一份渲染后的公式内容。
- 数学、物理、化学、生物、地理、历史、语文、英语、政治统一执行内容无关的表达式质量门，不按知识点维护补丁规则。
- 图形描述执行同一公式契约，最终 SVG 禁止出现内部传输标记、裸 LaTeX、美元公式或无效路径。
- 模型、图形提示词、`figure-specs.json`、温度、最大 token 与质量标准均保持不变；只修复响应观测、结构验证、缓存复检和重试编排。
- 图形批量任务逐题串行；每次模型响应记录完成原因、响应长度、完整 SVG 状态和质量失败码，失败项独立重试，成功项不重复调用。
- 缓存只保存通过共享 XML/安全/可见性质量门的 SVG；读取缓存时再次复检，浏览器复检拒绝时用 `forceRegenerate` 绕过对应缓存。
- 工具参数只接受一次指定函数调用；普通 `content`、错误工具、多工具调用、坏 JSON、额外字段和部分试卷全部拒绝，不提取、不修复。
- 单个命题任务内批次串行，整卷最多并行两个命题任务，优先降低供应商漏调用工具和格式偏移概率。
- 配置页采用“左侧组卷大纲 + 右侧当前知识点编辑器”的渐进式布局；左侧不展开完整考点参数，右侧一次只编辑一个知识点。
- 本地页面不在 `5100` 端口运行时，前端请求封装自动连接同主机的 `5100` API；生产环境继续使用同源 `/api`。
- 网络故障必须显示在页面工作区内，提供明确原因与重试连接动作，不向用户暴露 `Failed to fetch` 等底层英文异常。
- 题图统一使用 `400:300` 画布的 `280px × 210px` 视觉框；仅改变显示尺寸，不改变 SVG 内容、提示词或模型。
- Word 公式必须来自页面已通过 KaTeX 严格编译的 MathML，并完整转换为 OMML；任何公式转换失败、数量不一致、非法样式或源码残留都终止整个导出。
- Word 媒体目录只允许包含已验证的 2 倍像素题图 PNG，禁止生成公式图片；`.docx` 主文档中的 `<m:oMath>` 数量必须与预览公式数量完全一致。
- 继续生成固定为单知识点、单考点、单题型、3 道题；初始组卷成功后签发 `cg1` HMAC 能力凭证，凭证带过期时间且不依赖进程内存，追加不重复消耗体验额度，响应及新题题图未全部通过时不得修改原题目状态。
- PDF 的空白质量门不得放宽：只允许在分页前从总高度中排除最后可见正文之后的结构性白区；任何正文范围内部的空白页仍必须阻止导出。

## 高层实施计划

1. 创建功能契约文档与多知识点数据模型。
2. 重做前端知识点/考点配置交互，增加每个考点的题型计数器。
3. 改造生成接口和 AI 契约，按考点及题型强制工具调用、严格生成并合并。
4. 修复图形批量接口调用，移除图形兜底并强化失败阻断。
5. 引入 KaTeX，统一公式渲染与导出内容。
6. 运行构建、接口、浏览器、图形和导出回归验证。
7. 重构多知识点编辑动线并增加本地 API 地址解析、连接状态与失败恢复。
8. 统一题图视觉尺寸，增加全选状态机，并建立可阻断源码残留的 Word 导出质量门。
9. 建立 Node、Worker、浏览器共享 SVG 结构质量门，补齐响应诊断、缓存复检和失败题原子重试。
10. 修复 PDF 居中与原子分页，批量优化 Word 高清渲染，并增加题组级继续生成 3 题闭环。
11. 将继续生成改为题组级独立锁与操作级题图事务，允许不同题组并发，并在最终提交时解决题号竞争。
12. 本地打包 PDF/Word 渲染依赖；将题图当前导出结果与跨导出 LRU 分离，容量淘汰不得影响当前文件完整性。
13. PDF 使用混合分页：可容纳一页的题目/答案保持整块，超长父块按直接语义子块分页，任一子块过高仍拒绝导出。
14. 将 Word 升级为标准 `.docx` 与原生 OMML 公式，并把续题额度改为“单次组卷只扣一次”的会话凭证契约。
15. 将严格重试拆为“任务级重新生成 + 批次级审题纠正”：保留坏稿和机器错误，只重试失败批次，不做字符串修复或质量降级。
16. 修复 PDF 无损单图复用与有效裁剪路径；修复 Word OMML XML 序列化、分段定界符和长公式选项布局，并以 WPS 实机页面验证。
17. 将续题授权从内存会话随机值改为紧凑 HMAC 签名凭证，Node/Worker 对称验证并在成功追加后续签，覆盖服务重启与连续第二次追加。
18. 将 PDF 分页 API 改为物理画布高度与有效正文高度双边界，补充原始像素复核、导出专用加载状态和空白尾页对抗回归。

## 验证

- `npm run build` 必须通过。
- 多知识点请求必须返回每个考点的来源元数据与配置数量。
- 带 figure 题目必须在批量渲染成功前禁止组卷；SVG 失败接口返回明确错误。
- 预览中不得出现裸的 `\\frac`、`$...$`、`LATEXSLASH`、`@@BS@@`、`[[LATEX]]` 或未知反斜杠命令；PDF/Word 导出中保留公式和图形。
- Word 文件不得含 `<math>`、`<annotation>`、`.katex`、LaTeX 定界符、裸命令、非法 OMML 样式或私有传输标记；`<m:oMath>` 数量必须与预览公式数量完全一致，媒体目录不得出现公式图片。
- 所有题卡 SVG 在桌面端的渲染边界必须统一为 `280px × 210px`；全选按钮必须在“全选/取消全选”之间与单题选择状态同步切换。
- 九大学科合法与对抗式语料、任务级整卷重试、SVG 可见内容、真实 Edge 生成及 PDF/Word 成品必须全部通过。
- 截图场景必须真实返回 8 个题组、22 题、22 答案、22 条来源元数据；浏览器须得到 22 个有效 SVG，PDF 与 Word 须分别通过页面渲染、OMML 公式计数和题图 PNG 计数。
- 图形对抗测试必须覆盖截断响应、HTML 命名实体、标签错配、危险元素与属性、外部资源、非法 path 参数、无真实几何主体、隐藏或定义区伪图形、编码后的公式源码和非法命名空间。
- 截图中的圆与弦题必须用当前模型和原提示词真实生成；服务端日志须显示完整响应与 `finish_reason`，浏览器须得到 `280×210` 非空题图且控制台无错误。
- PDF 长卷逐页渲染后左右内容边界差必须可量化接近 0，任一原子块不得同时出现在相邻页的页尾和页头。
- Word 对抗夹具须验证 MathML→OMML 转换、mhchem 幻影节点语义还原、公式/题图数量完全一致及源码零残留。
- “继续生成3题”须验证桌面与 390px 移动端按钮可用、编号连续、同组追加、失败回滚和 Node/Worker 请求契约对称。
- 续题凭证须覆盖签名篡改、过期、模块重载、服务与会话完全重建、多个并发凭证和成功响应续签；真实浏览器须在初始生成后重启 `5100` 服务，原题不变并连续两次各追加 3 题。
- 继续生成固定 3 题的 `2+1` 批次须覆盖：首题 `answer` 连续输出裸命令、字段级纠错清单进入审核、第二次局部纠正成功、最终 3 题完整且坏内容零残留。
- 两个不同题组须能同时处于生成态；同组仍只能有一个事务。反向完成时内部索引不得重复，页面显示题号须按视觉顺序连续。
- Word 压力夹具须验证大量 OMML 公式不会进入媒体目录且主文档结构完整；PDF 压力夹具须同时覆盖短题整块和超长父块语义分页。
- PDF 性能夹具须保持 2 倍分辨率和无损像素，记录同一 25 题样本优化前后耗时；逐页渲染不得出现相邻页重复、切割或空白页。
- PDF 空白尾页夹具须覆盖短卷、长卷、正文位于分页线前后 `1px`、18 题及答案解析；修复前的纯白尾片必须可复现，修复后真实浏览器成功下载且 Poppler 每页非白。
- Word 必须通过 WPS 实际打开与页面渲染，重点验证 `<` 不等号、分段公式跨行花括号、长公式选项标签和题图；结构计数通过不能替代可见结果验收。

## 回滚

- 前端可回退到旧的单知识点表单；后端旧字段仍由规范化层支持。
- 如 KaTeX 或工具调用契约构建失败，只能恢复上一个已验证的完整版本，不得在运行时启用 JSON 修复、公式降级或占位图。
- 如 Word OMML 转换链路失败，只能阻止下载并恢复上一个已验证版本，不得回退为公式图片、裸 MathML、裸 LaTeX 或普通文本公式。
- 图形服务不再提供兜底图；回滚时只能恢复旧版本接口行为，不得混用新旧缓存。
- 如签名凭证链路异常，只能回滚到上一个完整验证版本并要求重新生成整卷；不得恢复进程内存凭证或放行未签名令牌。
