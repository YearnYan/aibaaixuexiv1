# 全学科公式渲染修复计划

## 问题陈述和动机

试卷内容在 AI 输出、JSON 解析和后处理过程中会丢失 LaTeX 反斜杠、公式分组或上下标结构，部分链路还会主动把 LaTeX 降级为 Unicode 与纯文本。浏览器端因此可能展示残留命令、控制字符或不规范的线性公式，教师和学生难以阅读。

## 范围

- 仅修改“试卷变式机”子网站。
- 覆盖上传原卷变式与该子网站保留的常规生成链路。
- 统一数学、物理、化学、生物、地理及其他 K12 学科中的公式、单位、方程式和专业符号格式。
- 覆盖题干、选项、答案、解析、大题标题、网页预览、PDF 和 Word 导出。
- 同步 Node 服务与 Cloudflare Worker 行为。

## 非目标

- 不修改其他子网站的生成、渲染或导出代码。
- 不改变试卷变式难度、变式系数、积分或题图业务规则。
- 不把图形描述改造成 LaTeX/TikZ 图形生成系统。

## 设计边界和约束

- LaTeX 是公式内容的唯一规范源，禁止服务端再将其破坏性转换为 Unicode 线性文本。
- 行内公式使用 `\(...\)`，独立公式使用 `\[...\]`，化学内容使用 KaTeX 的 `mhchem` 语法。
- JSON 中的 LaTeX 反斜杠必须在解析前得到保护，不能被 `\f`、`\t`、`\n` 等 JSON 转义误吞。
- 浏览器必须使用随构建产物发布的 KaTeX 与 mhchem，不依赖外部 CDN 可用性。
- 对不完整的旧内容做保守规范化；无法可靠识别的普通文字不得被误判为公式。

## 高层实施计划

1. 建立共享学科内容契约、JSON 安全解析和试卷字段规范化模块。
2. Node 与 Worker 生成链路共用该模块，移除 Unicode 降级后处理。
3. 前端捆绑 KaTeX + mhchem，统一渲染题干、选项、答案与解析。
4. 完善打印与导出样式，保证公式不溢出、不截断。
5. 使用多学科固定样例与回归测试验证生成、解析、渲染和构建。

## 验证

- 运行 60 秒内完成的 Node 单元测试。
- 对数学、物理、化学、生物、地理样例执行 KaTeX 严格渲染测试。
- 构建前端和 Worker，确认产物内包含本地公式引擎且不依赖 KaTeX CDN。
- 检查 Git 变更路径全部位于 `试卷变式机/`。

## 回滚

- 本次不涉及数据迁移或持久化结构变化，可按文件级变更回退共享模块、生成链路和前端依赖。
- 回滚时必须同时恢复 Node、Worker 与前端，避免公式契约不一致。
