# 上传原卷变式出卷

## 背景与问题

现有产品通过科目、年级、知识点、考点、题型、数量和难度等参数生成题目，用户仍需手动筛选和组卷。新的产品目标是让用户直接上传一份完整试卷，系统内部解析原卷，并生成题型、考点、难度和题目数量一一对应的变式卷。

真实全科试卷中还存在几何图、电路、实验装置、生物结构、地图、统计图、漫画、图片材料和英文图表等视觉载体。模型偶尔会在新题中保留“如图”“图1”或 `chart` 等引用，却漏掉可还原的题图描述。直接放行会产生无解题，整卷拒绝又会丢弃已经合格的其他题，因此必须建立逐题可恢复的题图完整性链路。

## 范围

- 删除左侧原有配置项和选项模块。
- 新增支持 JPG、PNG、PDF、DOC、DOCX 的多文件上传入口。
- AI 在后台解析原卷结构，不向用户展示中间分析。
- 直接生成完整变式卷，每道题对应原卷同序号题目。
- 保留现有 A4 预览、答案显示和 PDF、Word 导出能力。
- 对题图缺失或描述不可复现的题目执行定向修复，不重新生成整卷。
- 首轮允许补全精准题图；仍未通过时改写为不依赖视觉材料的自包含题。

## 非目标

- 不展示原卷解析报告。
- 不提供逐题手动选题和组卷流程。
- 不引入数据库持久化。
- 不用占位图、原图引用或删除“如图”字样的方式掩盖题目条件缺失。

## 约束

- 单次最多上传 60 个文件，总大小不超过 48MB，单文件不超过 18MB。
- PDF 尽量同时提取文本和页面图片，以覆盖扫描版试卷。
- 本地 Node 服务负责 DOC、DOCX 和 PDF 文本抽取。
- Worker 部署环境优先处理图片上传；无法稳定抽取的文件格式返回明确提示。
- 题图修复不得改变题号、题量、顺序、知识点、考点、目标难度和变式强度。
- 全科视觉引用使用同一共享契约，Node 与 Worker 不得维护不同的判断规则。

## 验证

- 上传框支持拖放和多选。
- 非支持格式会在前端被拒绝。
- 后端拒绝空文件、超限文件和不支持格式。
- 上传后生成结果直接进入 A4 预览。
- 构建命令成功执行。
- 跨数学、物理、化学、生物、地理、历史、语文、英语的视觉引用测试通过。
- 普通“函数图像性质”等概念表述不得被误判为缺图题。
- 修复只改问题题目，并保持其他题目、题量和顺序不变。
